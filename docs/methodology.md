# 指数计算与数据口径

## 固定规则版本

来源：`Polokikiki/Milkonomy`，commit `f0b9b315b70c0e2394be7ee1a57d2e9d86556d93`，游戏数据版本 `v1.20260927.0`。其 `public/CNAME` 指向 `www.milkonomy.top`。本环境无法直连该域名，因此公式与默认配置以对应公开源码为核验依据，并非对线上页面进行逐值比对。

默认配置对应 `src/pinia/stores/player.ts`、`src/common/config/index.ts` 和 `src/common/apis/player/index.ts`：

- 各技能等级 100，80 级工具强化 +10（神圣系列）。强化倍率表 +10 为 14.5。
- 10 个生活技能房间各 4 级；本技能效率增加 `4×1.5%`，所有生活房的全局稀有发现增加 `10×4×0.2%=8%`。
- Eye Watch、Red Culinary Hat、Enchanted Gloves、Collector's Boots 均 +10，按实际非战斗属性加成；无衣裤/背部/护符、无项链/耳环/戒指/口袋。
- 无社区增益、成就增益、神龛、封印或战斗房额外加成（仅默认模式）。
- 税率 `4%` 来源为 `src/common/constants/market.ts` 中 `SELL_TAX_FACTOR = 0.96`，固定不可调。

## 品种范围与流动性

八个细分技能各自选品。仅保留普通交易资源、食品、饮料对应的单一主产品行动；排除装备、护符、箱子产品、任务物、升级配方、混合采集区（防止同一产物被多个行动重复计算）。行动等级固定 ≥20，且不高于所用配置的技能基础等级（默认 100；玩家模式为实际等级）。

每个北京时间自然日，使用当日实际抓到的唯一时间戳样本计算：

1. 累加当日源数据的有效 `v`，得到 **当日已观测成交量**，固定须 ≥10,000。官方 `v` 是相应小时窗口的量，归档采样不连续，不能当作完整 24 小时量；重复时间戳只计一次。未知量不算零，也不能用报价代替成交量。
2. 不设报价覆盖率、价差或买卖价格交叉筛选。至少一个样本能够计算完整利润，包括材料、饮食、加工产物、精华及箱内所有非固定价掉落。计算所需报价缺失、`-1`、零价或非数值时，该样本无效；不补价。
3. 除冲泡外，按日均净利润降序、行动 ID 升序稳定排序，取前 3 个，成交量不参与排名。冲泡使用百分位名次（并列取平均名次，唯一品种分数为 1），按 `0.5×利润排名 + 0.5×已观测量排名`、利润、行动 ID 排序取前 3 个；负利润可以入选。
4. 综合指数汇集所属 n 个行业各自入选的最多 3×n 个品种，再按日均净利润、行动 ID 排序取前 5 个。此步骤不比较行业内百分位分数，也不再加入成交量权重。成分等权；合格候选不足上限时按实际数量，不为缺失行业补品种。

每日确定同一组成篮子后，才生成当日所有时点的指数。篮子中某个成分在一个时点缺少利润，整个时点的细分指数缺失，不减少分母或重新换股。空篮子不输出 0。综合指数仅要求其实际入选成分在该时点有效；未入选品种的缺价不影响综合指数。综合篮子亦全天固定，不在某时点缺价时改取其他品种。

这是每日事后描述性选品，不是使用前一天权重的投资回测。当前日随样本更新会重新选品，不适合解释为可交易投资组合收益。

## 当前玩家模式

点击「切换模式」读取当前挂载的游戏 React 组件；兼容 `mwi.game` / `mwi_common.game` 已暴露的实例，但不依赖它们。通过 `unsafeWindow` 只读 `characterSkillMap`、`actionTypeDrinkSlotsDict` / `actionTypeFoodSlotsDict`、`noncombatStats.drinkConcentration` 和服务器已计算的 `equipment/house/community/achievement/personal/mooPass/guildActionTypeBuffsDict`。游戏处理函数将消息中的 `…Map` 改名为页面状态中的 `…Dict`；读取器优先使用 `Dict`，仅在该字段不存在时兼容 `Map`。装备增益已包含实际强化等级，房屋增益已包含全局房间效果，不能再叠加默认装备或默认房屋。当前所选饮食单独按配方加浓度计算，不再叠加 `consumableActionTypeBuffsDict` 或已汇总的 `skillingActionTypeBuffsDict`。

只保留角色名、配置读取时间、技能等级、生产增益与饮食 ID，不读取或保存账号凭据，不拦截 WebSocket、不发送游戏请求。切换模式或点击「更新装备数据」时重新读取；页面显示配置读取时间。饮食按当前选择固定使用（包括经验茶成本），假定持续补充；不按库存数量限制生产，也不改成最佳饮食。战斗专用食品不参与生活指数。暂时性增益按读取时的配置冻结用于整段历史回算；不预测到期、不模拟任务触发的专属增益。

游戏状态不完整、未知饮食或未支持的比例增益会报错，不用默认值代替玩家配置。读配置、取行情、计算成功后才一起替换面板结果；失败保留上一模式。角色数据只留在内存，导出 JSON 才包含上述生产配置。游戏内部组件不是稳定 API，目前未用真实账号实测；若未来变更结构，默认模式仍可使用。

## 利润与最佳饮食

按用户确认口径：**原料、饮品按卖一（ask）买入，产物按买一（bid）卖出**。可用金币商店购买的材料按市场卖一与固定金币商店价孰低；不假定挂买单能成交。主产品、材料缺报价时直接排除该样本/饮食方案，不以 `-1` 价格算利润，也不以当前价填历史。相较 Milkonomy 对缺原料报价的自制成本回退，本脚本采取更严格的缺数据排除，避免将无法成交的材料视作立即可以买到。

定义：

```
属性 = 装备基础属性 + 强化每级属性 × 倍率表[10] + 对应房屋加成 + 饮品加成
有效等级 = 配置技能等级 + 各来源等级加成 - 工匠茶等级惩罚
效率 = 1 + max(0, (有效等级 - 行动等级) × 0.01) + 效率加成
每小时行动数 = 3600 / max(3, 基础秒数 / (1 + 速度加成)) × 效率
采集主产量/次 = (最小数量 + 最大数量)/2 + 采集加成
制造材料/次 = 配方数量 × (1 - 工匠加成)
制造产物/次 = 配方数量 × (1 + 美食加成)
精华期望/次 = 最大数量 × 掉率 × (1 + 精华发现)
稀有期望/次 = 最大数量 × 掉率 × (1 + 稀有发现)
饮品消耗/小时 = 12 × (1 + 饮品浓度)
日利润 = 24 × (每小时税后产物收入 - 每小时材料成本 - 每小时饮品成本)
```

加工茶将主原料按加工概率扣除，并按相应配方原料数量（通常 2:1）计入奶酪/木板/布料，不重复计原料收入。没有加工配方的商品不扣主产品。沿用 Milkonomy 的采集均值、精华/稀有最大数量规则，而非随机抽样模拟。

默认模式每个品种、每个行情时点枚举适用饮品 0–3 槽，按 buff 的 `uniqueHrid` 排除普通/超级/究极同类型叠加。按扣除消费后的净利润选最大者。只增加经验而不增加金币产出的茶不优于空槽，因此不列入利润候选；食品只适用于战斗，不参与生活技能计算。成分表中的最佳饮食为当日期末有效样本的组合；日均利润反映各个时点各自最优组合。

### 箱子与牛铃

工匠箱、陨石箱等不可交易掉落不是零收入。按 `openableLootDropMap` 递归求开箱均值：`sum(掉率×(最小数量+最大数量)/2×内含物品买一价)`。牛铃以 `10 牛铃袋买一/10` 折算；没有袋子买一时沿用 Milkonomy 的固定估值 **40,000 金币/牛铃**。这项网站回退估值是唯一允许的非金币固定卖出估值，源码中显式声明，不能解释成真实市场报价。

直接金币产出不征税；**箱子整体估值乘卖出税因子，连同箱内金币部分**，以匹配 Milkonomy 的 `getLootPrice` + `income` 组合实现。此处是网站口径，而不是声称游戏对开箱金币收税。箱内可交易材料缺价则整个样本无效，不偷偷忽略随机收入。成分表「额外收入/日」为精华和稀有掉落的税后期望收入，已包含在利润中，不要重复相加。

## 指数与 K 线

- 时点细分指数：该日篮子内每种商品的 `24×每小时净利润` 算术平均，内部及 JSON 单位金币/日；全部界面金额除以 1,000,000 后以 M/日显示。
- 三采的候选来自挤奶、采集、伐木；三制造来自锻造、缝纫、制作；饮食来自烹饪、冲泡。每个综合指数取候选中日均利润前五，对入选品种的时点利润等权平均。
- 日线：北京时间 00:00–24:00，将有效时点指数按时间排序，首个为开、最大为高、最小为低、末个为收。**日均利润为观测样本均值**，采样不规则时不等于精确时间加权日均；不推断缺失时段。
- 周线：北京时间周一开始；月线：自然月。开取首日开、收取末日收、高低取所有有效日高低极值。周期日均为每日均值等权平均，不因某日采样更多而增加该日权重。
- 当前日/周/月都是未必完成的周期；只包括已获得样本。只有一个样本时 O=H=L=C，明确提示没有日内波动信息。
- 显示的高低点是采样指数高低，不能代表连续真实成交利润高低。不能对每种原材料的独立最高最低价做相减来伪造指数 OHLC。
- 历史期间始终采用当前固定快照配方/装备/税率，不试图恢复历次版本补丁，也不代表账户实赚。

## 报价与涨跌幅

卡片报价显示所选末根 K 线的收盘利润指数。默认选择最新一根；单击选择一根，Shift＋单击扩展区间，也可通过「选取区间」依次点选两端或使用「全部范围」。区间端点按时间先后处理，成分表显示期末实际成分。

- 单根涨跌额 = 本根收盘 − 前一可用周期收盘。
- 区间涨跌额 = 区间末根收盘 − 区间首根之前的可用周期收盘；不累加每日百分比。
- 涨跌幅 = 涨跌额 / abs(比较基准收盘) × 100%。负利润采用绝对值分母，使亏损收窄的方向为上涨。
- 前收缺失：金额及百分比显示不可计算，不回退到开盘；前收为零：金额正常显示、百分比不可计算。上涨红色、下跌绿色、持平或无比较基准为灰色。蜡烛实体仍按自身收开关系配色。
- 周/月线先聚合完整的可用历史，再按显示范围截取，保留范围之外的上一周期作为比较基准；缺日不补价。悬停涨跌文字可看到实际基准日期与数值。
- 金额变化仍为日利润估值的变化（M/日），不是把每天利润相加得到的区间收入。跨日成分更换会影响指数变化。

## 历史与缓存

默认加载上游最近 60 天的原始日内报价分片。上游更早数据是 UTC 日内报价中位数（不是 OHLC），因此严格剔除。不会从日中位数生成日内蜡烛，也不自动使用已停止更新且无成交量的 MWIApi 替换当前市场。

物品分片并发上限 4，每次请求 25 秒超时、最多重试一次；`@connect` 只允许 `raw.githubusercontent.com`。物品路径校验，拒绝外部 URL/路径跳转。原始行情和分片存入当前游戏来源的 IndexedDB；新快照按精确时间戳去重，不跨时间前向填价。积累最多 400 天。刷新失败可使用已有缓存，但显示失败/过期提示；首次无缓存失败则显示重试入口，无模拟图或零值假数据。

价格与成交量数据来自第三方归档，有缺口；流动性门槛是固定的选品规则，不能保证指定数量的交易实际全部成交。界面与导出保留样本数、成交量、成分、数据日期、计算规则和数据问题。
